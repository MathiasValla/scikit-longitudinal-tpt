Abstract

We present the Time-penalized Trees (TpT) splitter as implemented in scikit-longitudinal, a Python package for longitudinal machine learning. TpT extends recursive partitioning to repeated-measures covariates by penalizing candidate splits that rely on later observation waves. We describe the underlying split criterion, summarize the main user-facing parameters, and illustrate the implementation on two public longitudinal datasets: a subject-level classification problem based on the primary biliary cirrhosis follow-up data and a state-level regression problem based on the Produc panel. These examples show how the time penalty affects the selected split times and how the exported trees reveal both which predictors matter and when they matter.

1 Introduction

scikit-longitudinal extends the scikit-learn ecosystem with estimators and workflows tailored to repeated-measures data (Provost and Freitas 2025). This article focuses on the Time-penalized Trees (TpT) splitter, a decision-tree split rule designed for longitudinal covariates (Valla 2024). Rather than reproducing the full methodological development, we document the current TpT API in the package and provide two compact, fully reproducible real-data examples. Beyond the original algorithmic presentation, a recent theoretical analysis shows that TpT is a consistent estimator along a non-empty set of observation times under explicit structural assumptions (Valla and Milhaud 2026).

Tree-based methods for longitudinal or clustered data already span several families. Model-based recursive partitioning and generalized linear model trees target subgroup structure through parameter-instability ideas (Zeileis, Hothorn, and Hornik 2008; Seibold, Hothorn, and Zeileis 2019). RE-EM trees and mixed-effects random forests incorporate random effects to account for within-subject or within-cluster dependence (Sela and Simonoff 2012; Hajjem, Bellavance, and Larocque 2014). Survival-tree extensions such as LTRC trees can also accommodate time-varying covariates in censored settings (Fu and Simonoff 2017). TpT occupies a narrower but complementary niche: it keeps a CART-style impurity objective and modifies the split-selection criterion through an explicit time penalty, making the fitted tree directly readable in terms of both predictor and wave (Valla 2024).

The repository is structured as required by Computo (Computo Team 2020): the paper is written in Quarto, the environment is frozen in environment.yml, and the data preparation and analysis code are kept alongside the manuscript.

2 The TpT splitter in scikit-longitudinal

Recursive partitioning grows a tree by repeatedly splitting a parent node into child nodes that are more homogeneous with respect to the target variable. In other words, each split is chosen to reduce within-node heterogeneity, or equivalently to maximize the loss of impurity from the parent node to its children (Breiman et al. 1984).

For a classification node g, let p_k(g) denote the proportion of class k \in \{1, \ldots, K\} inside the node. An impurity measure should be nonnegative, equal to 0 when the node is pure, maximal at the uniform class distribution, and symmetric in the class labels. Two standard choices are the entropy

I_{\text{Ent}}(g) = -\sum_{k=1}^{K} p_k(g)\log p_k(g)

and the Gini impurity

I_{\text{Gini}}(g) = \sum_{k=1}^{K} p_k(g)\left(1 - p_k(g)\right) = 1 - \sum_{k=1}^{K} p_k(g)^2.

For regression, CART typically uses the node mean squared error

I_{\text{MSE}}(g) = \frac{1}{N(g)} \sum_{i: x^{(i)} \in g} \left(y^{(i)} - \bar y_g\right)^2,

where \bar y_g is the empirical mean response in node g. If a parent node g_p is split into left and right child nodes g_l and g_r, the usual CART goodness-of-split is the impurity decrease

\Delta I(g_p; g_l, g_r) = I(g_p) - \left[ \frac{N(g_l)}{N(g_p)} I(g_l) + \frac{N(g_r)}{N(g_p)} I(g_r) \right],

with I(g) standing for one of the classification impurities above, or for the MSE in regression.

At a tree node associated with parent time index t_p, TpT modifies this criterion and scores a candidate split at time t_c by multiplying the usual impurity improvement \Delta I by an exponential time penalty:

G_{\gamma} = \Delta I \exp \left[-\gamma (t_c - t_p)\right].

The hyperparameter \gamma \ge 0 controls how strongly later measurements are penalized. When \gamma = 0, TpT reduces to ordinary impurity-based split selection. As \gamma increases, the tree becomes more reluctant to use later waves unless they bring a clearly stronger impurity reduction.

From a user perspective, the main entry points are TpTDecisionTreeClassifier and TpTDecisionTreeRegressor. Both can consume LONG-format data directly by specifying an identifier column, an observation-time column and a subject-specific duration column.

The same splitter can also be reached from an explicit wide matrix together with features_group metadata. We use both entry points below: the pbcseq example illustrates direct long-format fitting, while the Produc example makes the long-to-wide conversion explicit.

For this article, we select \gamma on a small candidate grid by minimizing the fitted tree’s weighted total leaf impurity on the training split. This is a pragmatic paper-specific heuristic whose only goal is to keep the examples deterministic and easy to rerun; it should not yet be interpreted as a recommended general tuning rule for applied work.

2.1 A compact theoretical guarantee

TpT is not only a practical heuristic. In Valla and Milhaud (2026), the analysis focuses on record-high times, that is, feasible times whose penalized population envelope dominates all later competitors. The main result requires separated penalized-envelope gaps (Assumption A1), finite-sample attainability of the corresponding envelope peaks (Assumption A2), the TpT-\alpha branch-growing rule, and the regularity and noise assumptions needed to invoke the Klusowski-Tian oracle inequality for depth-K CART estimators (Klusowski and Tian 2024).

Theorem 1 Valla and Milhaud (2026). Assume (A1)–(A2), the TpT-\alpha growing rule, and the regularity and noise conditions required to apply the Klusowski-Tian oracle inequality for depth-K CART estimators. For every fixed record-high time t_k such that the approximation bias vanishes as K(t_k) \to \infty, the estimator fitted on the realized t_k-subtree satisfies

\mathbb{E}\!\left[\left\lVert \hat f_{t_k, K(t_k)} - f_{t_k}^{\star} \right\rVert^2_{L^2(P_{X(t_k)})}\right] \longrightarrow 0 \qquad \text{as } n \to \infty.

This is intentionally narrower than a blanket consistency claim over all time indices. The result identifies a non-empty sequence of times at which the penalized TpT rule recovers a consistent subtree estimator. We include this result only to summarize the current theoretical status of TpT; the paper itself remains focused on software usage. For an implementation-focused article, the practical takeaway is that the TpT framework underlying the splitter now has a precise asymptotic analysis, even though the present package implementation is discussed here from an operational rather than theorem-verification standpoint.

NoteCurrent scope

The present implementation is suitable for compact reproducible examples and software-oriented demonstrations. Missing-value routing inside the Cython TpT splitter is still treated as future work, and monotonic constraints are explicitly disabled for TpT at the wrapper level.

4 Install, quick start, and main parameters

The official scikit-longitudinal getting-started guide is intentionally lightweight, and the same philosophy fits this article well. For a standard Python environment, the minimal installation is:

pip install scikit-longitudinal

For LONG-format data, the shortest end-to-end TpT workflow is to pass a subject identifier, an observation-time column, a subject-level duration column, and the names of the longitudinal predictors:

from scikit_longitudinal.estimators.trees import TpTDecisionTreeClassifier

This article keeps the examples at the estimator level, but the API is compatible with these larger package workflows. In particular, the two examples below are meant to bridge the package documentation and practical usage: pbcseq uses the long-format wrapper directly, whereas Produc shows the explicit conversion and the low-level features_group interface.

5 Data sets

The two examples use small public repeated-measures datasets with complementary temporal structures, summarized in Table 2. We cite scikit-longitudinal through its JOSS software paper (Provost and Freitas 2025). The pbcseq data contain follow-up laboratory measurements for the randomized Mayo Clinic primary biliary cirrhosis trial, with visits planned at 6 months, 1 year, and yearly thereafter (Therneau, Terry 2025). The Produc data form a balanced annual panel of 48 US states from 1970 to 1986 (Munnell, Alicia H. 2025). Together they provide two deliberately different views of TpT: a subject-level clinical classification problem with irregular follow-up, and a compact multi-wave regression panel where the effect of \gamma on selected split times is easy to inspect.

6 Example 1: Subject-level classification on pbcseq

Our classification example uses pbcseq, the sequential primary biliary cirrhosis follow-up data distributed with the survival package (Therneau, Terry 2025). We keep four complete longitudinal biomarkers (bili, albumin, protime, ast), use day as the observation-time variable, futime as the subject-specific horizon, and define a binary target equal to one when the subject experiences either transplantation or death by the end of follow-up. In the processed version used here, this yields 312 subjects, 1,945 recorded visits, and a median of 5 visits per subject (Table 2).

The example is run on a subject-level train/test split, with the long-format API of TpTDecisionTreeClassifier. The minimal fit/predict workflow is:

Hide/Show the code 
from scikit_longitudinal.estimators.trees import TpTDecisionTreeClassifier

7 Example 2: State-level regression on Produc

Our regression example uses Produc, a public US state production panel available through Rdatasets (Munnell, Alicia H. 2025). The source data contain 48 states followed yearly from 1970 to 1986. We keep three longitudinal predictors available at each wave: private capital stock (pc), employment (emp), and unemployment rate (unemp). For each state, we hold out the final recorded gross state product and predict that final_gsp from the preceding 16 yearly observations. We keep Produc deliberately: although it is an economic panel rather than an individual-level biomedical cohort, its 17 annual waves and three interpretable predictors make the effect of the TpT time penalty easy to see in a small real dataset. To keep the example readable while still producing a nonzero selected gamma and non-baseline splits on the training impurity criterion, we use the predictor subset pc, emp, and unemp together with a depth-4 tree, min_samples_leaf=1, and min_samples_split=2.

In this example we explicitly use the TpT conversion helper long_to_wide(...), then fit the regressor on the resulting wide matrix and its feature_groups metadata. The minimal workflow is:

Hide/Show the code 
from scikit_longitudinal.estimators.trees import TpTDecisionTreeRegressor
from scikit_longitudinal.estimators.trees.TpT._preprocessing import long_to_wide

feature_columns = ["state", "time_index", "duration", "pc", "emp", "unemp"]

wide_train = long_to_wide(
    train_df[feature_columns],
    id_col="state",
    time_col="time_index",
    duration_col="duration",
    time_step=1.0,
    feature_columns=["pc", "emp", "unemp"],
    target=train_df["final_gsp"],
)

reg = TpTDecisionTreeRegressor(
    gamma=selected_gamma,
    criterion="squared_error",
    max_depth=4,
    min_samples_leaf=1,
    min_samples_split=2,
    random_state=42,
    features_group=wide_train.feature_groups,
)

reg.fit(wide_train.X, wide_train.y)
pred = reg.predict(wide_test.X)

The selected regression tree can also be shown directly with the dedicated plot_tree exporter.

On the article grid from 0.000 to 0.100 by 0.001, the selected regression gamma is 0.011. The corresponding tree still uses later history, with selected split times between waves 1 and 5. As gamma increases further on that grid, the tree is pulled back toward baseline: the root split moves to wave 0 by about gamma = 0.031, and from about gamma = 0.055 onward all selected split times are at baseline. The gamma path therefore shows the intended TpT tradeoff quite clearly: modest penalization still allows mid-history splits when they materially reduce impurity, whereas stronger penalization progressively collapses the tree toward earlier waves.

8 Discussion

These two examples are intentionally small. Their role is not to provide a full benchmarking study, but to document a reproducible and inspectable usage path for TpT within scikit-longitudinal. Together they show that TpT can be fit either directly from LONG-format data or from an explicit wide matrix, tuned with a simple deterministic gamma heuristic for demonstration purposes, and exported as readable wave-indexed trees.

Most importantly for this article, the exported trees show both what matters and when it matters. In pbcseq, the classifier can isolate clinically meaningful biomarker thresholds at specific follow-up waves rather than collapsing the history into a single summary. In Produc, the regression tree reveals whether private capital, employment, or unemployment becomes informative early or later in the state-level trajectory. This predictor-plus-wave readability is the main practical property we wanted to make visible.

The paper also has clear limits. We deliberately keep the methodological discussion short, we do not attempt a large comparative benchmark, and the gamma-selection rule used here is only a reproducible placeholder rather than a definitive model-selection recommendation. On the software side, missing-value routing inside the Cython TpT splitter is still future work.

Natural next steps are equally clear: implement survival-specific evaluation metrics, add richer visualization utilities such as subject-level trajectory displays inside the fitted tree, build ensemble methods on top of the current splitter, and generalize the time penalty so that prior temporal structure such as lagged predictor effects can be encoded directly. Because TpT is now integrated into the tree-building backend, these extensions are largely a question of design and validation rather than reimplementing the core split rule from scratch.

Within that scope, TpT already has the ingredients of a useful scikit-longitudinal contribution: a lightweight API, interpretable exported trees, and a growing theoretical foundation.

# Introduction

`scikit-longitudinal` extends the `scikit-learn` ecosystem with estimators and
workflows tailored to repeated-measures data [@provost2025sklong]. This article
focuses on the Time-penalized Trees (TpT) splitter, a decision-tree split
rule designed for longitudinal covariates [@valla2024tpt]. Rather than
reproducing the full methodological development, we document the current TpT API
in the package and provide two compact, fully reproducible real-data examples.
Beyond the original algorithmic presentation, a recent theoretical analysis
shows that TpT is a consistent estimator along a non-empty set of observation
times under explicit structural assumptions [@valla2026consistency].

Tree-based methods for longitudinal or clustered data already span several
families. Model-based recursive partitioning and generalized linear model trees
target subgroup structure through parameter-instability ideas
[@zeileis2008mob; @seibold2019glmtrees]. RE-EM trees and mixed-effects random
forests incorporate random effects to account for within-subject or within-cluster
dependence [@sela2012reem; @hajjem2014merf]. Survival-tree extensions such as
LTRC trees can also accommodate time-varying covariates in censored settings
[@fu2017ltrc]. TpT occupies a narrower but complementary niche: it keeps a
CART-style impurity objective and modifies the split-selection criterion through
an explicit time penalty, making the fitted tree directly readable in terms of
both predictor and wave [@valla2024tpt].

The repository is structured as required by Computo [@computo]: the paper is
written in Quarto, the environment is frozen in `environment.yml`, and the data
preparation and analysis code are kept alongside the manuscript.

# The TpT splitter in `scikit-longitudinal`

Recursive partitioning grows a tree by repeatedly splitting a parent node into
child nodes that are more homogeneous with respect to the target variable. In
other words, each split is chosen to reduce within-node heterogeneity, or
equivalently to maximize the loss of impurity from the parent node to its
children [@breiman1984cart].

For a classification node $g$, let $p_k(g)$ denote the proportion of class
$k \in \{1, \ldots, K\}$ inside the node. An impurity measure should be
nonnegative, equal to $0$ when the node is pure, maximal at the uniform class
distribution, and symmetric in the class labels. Two standard choices are the
entropy

$$
I_{\text{Ent}}(g) = -\sum_{k=1}^{K} p_k(g)\log p_k(g)
$$

and the Gini impurity

$$
I_{\text{Gini}}(g) = \sum_{k=1}^{K} p_k(g)\left(1 - p_k(g)\right)
= 1 - \sum_{k=1}^{K} p_k(g)^2.
$$

For regression, CART typically uses the node mean squared error

$$
I_{\text{MSE}}(g) = \frac{1}{N(g)}
\sum_{i: x^{(i)} \in g} \left(y^{(i)} - \bar y_g\right)^2,
$$

where $\bar y_g$ is the empirical mean response in node $g$. If a parent node
$g_p$ is split into left and right child nodes $g_l$ and $g_r$, the usual CART
goodness-of-split is the impurity decrease

$$
\Delta I(g_p; g_l, g_r) =
I(g_p) -
\left[
\frac{N(g_l)}{N(g_p)} I(g_l) +
\frac{N(g_r)}{N(g_p)} I(g_r)
\right],
$$

with $I(g)$ standing for one of the classification impurities above, or for the
MSE in regression.

At a tree node associated with parent time index $t_p$, TpT modifies this
criterion and scores a candidate split at time $t_c$ by multiplying the usual
impurity improvement $\Delta I$ by an exponential time penalty:

$$
G_{\gamma} = \Delta I \exp \left[-\gamma (t_c - t_p)\right].
$$

The hyperparameter $\gamma \ge 0$ controls how strongly later measurements are
penalized. When $\gamma = 0$, TpT reduces to ordinary impurity-based split
selection. As $\gamma$ increases, the tree becomes more reluctant to use later
waves unless they bring a clearly stronger impurity reduction.

From a user perspective, the main entry points are
`TpTDecisionTreeClassifier` and `TpTDecisionTreeRegressor`. Both can consume
LONG-format data directly by specifying an identifier column, an observation-time
column and a subject-specific duration column.

The same splitter can also be reached from an explicit wide matrix together
with `features_group` metadata. We use both entry points below:
the `pbcseq` example illustrates direct long-format fitting, while the `Produc`
example makes the long-to-wide conversion explicit.

For this article, we select $\gamma$ on a small candidate grid
by minimizing the fitted tree's weighted total leaf impurity on the training
split. This is a pragmatic paper-specific heuristic whose only goal is to keep
the examples deterministic and easy to rerun; it should not yet be interpreted
as a recommended general tuning rule for applied work.

## A compact theoretical guarantee

TpT is not only a practical heuristic. In @valla2026consistency, the analysis
focuses on record-high times, that is, feasible times whose penalized
population envelope dominates all later competitors. The main result requires
separated penalized-envelope gaps (Assumption A1), finite-sample attainability
of the corresponding envelope peaks (Assumption A2), the TpT-$\alpha$
branch-growing rule, and the regularity and noise assumptions needed to invoke
the Klusowski-Tian oracle inequality for depth-$K$ CART estimators
[@klusowski2024cart].

::: {.theorem}
**Theorem 1 Valla and Milhaud (2026).**
Assume (A1)--(A2), the TpT-$\alpha$ growing rule, and the regularity and noise
conditions required to apply the Klusowski-Tian oracle inequality for depth-$K$
CART estimators. For every fixed record-high time $t_k$ such that the
approximation bias vanishes as $K(t_k) \to \infty$, the estimator fitted on the
realized $t_k$-subtree satisfies

$$
\mathbb{E}\!\left[\left\lVert \hat f_{t_k, K(t_k)} - f_{t_k}^{\star} \right\rVert^2_{L^2(P_{X(t_k)})}\right]
\longrightarrow 0
\qquad \text{as } n \to \infty.
$$
:::

This is intentionally narrower than a blanket consistency claim over all time
indices. The result identifies a non-empty sequence of times at which the
penalized TpT rule recovers a consistent subtree estimator. We include this
result only to summarize the current theoretical status of TpT; the paper itself
remains focused on software usage. For an implementation-focused article, the practical
takeaway is that the TpT framework underlying the splitter now has a precise
asymptotic analysis, even though the present package implementation is discussed
here from an operational rather than theorem-verification standpoint.

::: {.callout-note}
## Current scope

The present implementation is suitable for compact reproducible examples and
software-oriented demonstrations. Missing-value routing inside the Cython TpT
splitter is still treated as future work, and monotonic constraints are
explicitly disabled for TpT at the wrapper level.
:::

# Example 2: State-level regression on `Produc`

Our regression example uses `Produc`, a public US state production panel
available through Rdatasets [@dataset-produc]. The source data contain
48 states followed yearly from 1970 to 1986. We keep three longitudinal
predictors available at each wave: private capital stock (`pc`), employment
(`emp`), and unemployment rate (`unemp`).
For each state, we hold out the final recorded gross state product and predict
that `final_gsp` from the preceding 16 yearly observations. We keep `Produc`
deliberately: although it is an economic panel rather than an individual-level
biomedical cohort, its 17 annual waves and three interpretable predictors make
the effect of the TpT time penalty easy to see in a small real dataset. To keep
the example readable while still producing a nonzero selected gamma and
non-baseline splits on the training impurity criterion, we use the predictor
subset `pc`, `emp`, and `unemp` together with a depth-4 tree,
`min_samples_leaf=1`, and `min_samples_split=2`.

In this example we explicitly use the TpT conversion helper
`long_to_wide(...)`, then fit the regressor on the resulting wide matrix and its
`feature_groups` metadata. The minimal workflow is:

```{python}
#| eval: false
from scikit_longitudinal.estimators.trees import TpTDecisionTreeRegressor
from scikit_longitudinal.estimators.trees.TpT._preprocessing import long_to_wide

feature_columns = ["state", "time_index", "duration", "pc", "emp", "unemp"]

wide_train = long_to_wide(
    train_df[feature_columns],
    id_col="state",
    time_col="time_index",
    duration_col="duration",
    time_step=1.0,
    feature_columns=["pc", "emp", "unemp"],
    target=train_df["final_gsp"],
)

reg = TpTDecisionTreeRegressor(
    gamma=selected_gamma,
    criterion="squared_error",
    max_depth=4,
    min_samples_leaf=1,
    min_samples_split=2,
    random_state=42,
    features_group=wide_train.feature_groups,
)

reg.fit(wide_train.X, wide_train.y)
pred = reg.predict(wide_test.X)
```

The selected regression tree can also be shown directly with the dedicated
`plot_tree` exporter.

On the article grid from `0.000` to `0.100` by `0.001`, the selected
regression gamma is `0.011`. The corresponding tree still uses later history,
with selected split times between waves 1 and 5. As gamma increases further on
that grid, the tree is pulled back toward baseline: the root split moves to
wave 0 by about `gamma = 0.031`, and from about `gamma = 0.055` onward all
selected split times are at baseline. The gamma path therefore shows the
intended TpT tradeoff quite clearly: modest penalization still allows
mid-history splits when they materially reduce impurity, whereas stronger
penalization progressively collapses the tree toward earlier waves.

# Discussion

These two examples are intentionally small. Their role is not to provide a full
benchmarking study, but to document a reproducible and inspectable usage path
for TpT within `scikit-longitudinal`. Together they show that TpT can be fit
either directly from LONG-format data or from an explicit wide matrix, tuned
with a simple deterministic gamma heuristic for demonstration purposes, and
exported as readable wave-indexed trees.

Most importantly for this article, the exported trees show both what matters and
when it matters. In `pbcseq`, the classifier can isolate clinically meaningful
biomarker thresholds at specific follow-up waves rather than collapsing the
history into a single summary. In `Produc`, the regression tree reveals whether
private capital, employment, or unemployment becomes informative early or later
in the state-level trajectory. This predictor-plus-wave readability is the main
practical property we wanted to make visible.

The paper also has clear limits. We deliberately keep the methodological
discussion short, we do not attempt a large comparative benchmark, and the
gamma-selection rule used here is only a reproducible placeholder rather than a
definitive model-selection recommendation. On the software side, missing-value
routing inside the Cython TpT splitter is still future work.

Natural next steps are equally clear: implement survival-specific evaluation
metrics, add richer visualization utilities such as subject-level trajectory
displays inside the fitted tree, build ensemble methods on top of the current
splitter, and generalize the time penalty so that prior temporal structure such
as lagged predictor effects can be encoded directly. Because TpT is now
integrated into the tree-building backend, these extensions are largely a
question of design and validation rather than reimplementing the core split rule
from scratch.

Within that scope, TpT already has the ingredients of a useful
`scikit-longitudinal` contribution: a lightweight API, interpretable exported
trees, and a growing theoretical foundation.
