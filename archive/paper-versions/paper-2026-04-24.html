Abstract

We present the Time-penalized Trees (TpT) splitter as implemented in scikit-longitudinal, a Python package for longitudinal machine learning. TpT extends recursive partitioning to repeated-measures covariates by penalizing candidate splits that rely on later observation waves. We describe the underlying split criterion, summarize the main user-facing parameters, and illustrate the implementation on two public longitudinal datasets: a subject-level classification problem based on the primary biliary cirrhosis follow-up data and a state-level regression problem based on the Produc panel. These examples show how the time penalty affects the selected split times and how the exported trees reveal both which predictors matter and when they matter.

1 Introduction

Longitudinal data, characterised by repeated measurements of the same variables over successive time points (referred to as waves), are common in medicine, economics, and the social sciences. Unlike ordinary tabular data, they carry a temporal structure across repeated measurements of the same covariate, and that structure is easily lost under standard preprocessing. scikit-longitudinal (Sklong) is an open-source Python library that addresses these challenges by providing tools for machine learning on longitudinal data while remaining close to the familiar scikit-learn ecosystem (Provost and Freitas 2025).

This article introduces the Time-penalized Trees (TpT) (Valla 2024), a recent primitive of Sklong that adds a new longitudinal-data-aware decision-tree splitter to the library. It extends standard split selection to longitudinal data by penalizing candidate splits placed at later observation waves, allowing earlier measurements to be preferred when impurity reduction is comparable.

Instead of reproducing the full methodological development of TpT (Valla 2024), we focus on the software side of the contribution, structured as follows. We first present the TpT split criterion in Sklong and briefly recap a recent theoretical analysis showing that TpT is a consistent estimator across a non-empty set of observation times under explicit structural assumptions (Valla and Milhaud 2026). Second, we describe the reproducible setup adopted throughout the paper, including the Python environment and the data preparation pipeline. Third, we document the TpT Application Programming Interface (API), walking through installation, reshaping, and the main hyperparameters. We then present two computational examples on public longitudinal datasets, one classification and one regression, to illustrate the splitter’s behaviour. We conclude with a short discussion of the splitter’s current scope and limitations, and of directions for future work.

Tree-based methods for longitudinal or clustered data already span several families. Model-based recursive partitioning and generalized linear model trees target subgroup structure through parameter-instability ideas (Zeileis, Hothorn, and Hornik 2008; Seibold, Hothorn, and Zeileis 2019). RE-EM trees and mixed-effects random forests incorporate random effects to account for within-subject or within-cluster dependence (Sela and Simonoff 2012; Hajjem, Bellavance, and Larocque 2014). Survival-tree extensions such as LTRC trees can also accommodate time-varying covariates in censored settings (Fu and Simonoff 2017). Closer to TpT, lexicographic optimisation approaches to longitudinal decision-tree classifiers keep the standard split score and break ties in favour of more recent features, yielding models that lean on later waves (Ribeiro and Freitas 2024). TpT occupies a complementary niche: it keeps the CART impurity objective itself and modifies the split-selection criterion through an explicit time penalty, making the fitted tree directly readable in terms of both predictor and wave (Valla 2024).

The repository is structured as required by Computo (Computo Team 2020): the paper is written in Quarto, the environment is frozen in environment.yml, and the data preparation and analysis code are kept alongside the manuscript.

2 The TpT splitter in scikit-longitudinal

Recursive partitioning grows a tree by repeatedly splitting a parent node into child nodes that are more homogeneous with respect to the target variable. In other words, each split is chosen to reduce within-node heterogeneity, or equivalently to maximize the loss of impurity from the parent node to its children (Breiman et al. 1984).

For a classification node g, let p_k(g) denote the proportion of class k \in \{1, \ldots, K\} inside the node. An impurity measure should be nonnegative, equal to 0 when the node is pure, maximal at the uniform class distribution, and symmetric in the class labels. Two standard choices are the entropy

I_{\text{Ent}}(g) = -\sum_{k=1}^{K} p_k(g)\log p_k(g)

and the Gini impurity

I_{\text{Gini}}(g) = \sum_{k=1}^{K} p_k(g)\left(1 - p_k(g)\right) = 1 - \sum_{k=1}^{K} p_k(g)^2.

For regression, CART typically uses the node mean squared error

I_{\text{MSE}}(g) = \frac{1}{N(g)} \sum_{i: x^{(i)} \in g} \left(y^{(i)} - \bar y_g\right)^2,

where \bar y_g is the empirical mean response in node g. If a parent node g_p is split into left and right child nodes g_l and g_r, the usual CART goodness-of-split is the impurity decrease

\Delta I(g_p; g_l, g_r) = I(g_p) - \left[ \frac{N(g_l)}{N(g_p)} I(g_l) + \frac{N(g_r)}{N(g_p)} I(g_r) \right],

with I(g) standing for one of the classification impurities above, or for the MSE in regression.

At a tree node associated with parent time index t_p, TpT modifies this criterion and scores a candidate split at time t_c by multiplying the usual impurity improvement \Delta I by an exponential time penalty:

G_{\gamma} = \Delta I \exp \left[-\gamma (t_c - t_p)\right].

The hyperparameter \gamma \ge 0 controls how strongly later measurements are penalized. When \gamma = 0, TpT reduces to ordinary impurity-based split selection. As \gamma increases, the tree becomes more reluctant to use later waves unless they bring a clearly stronger impurity reduction.

From a user perspective, the main entry points are TpTDecisionTreeClassifier and TpTDecisionTreeRegressor. Both estimators operate on wide-format data together with features_group metadata that encodes which columns belong to the same longitudinal feature across waves. Long-format data must therefore be converted to wide-format beforehand, which is handled in Sklong by the public LongitudinalDataset.to_wide API (documentation; tutorial). We use this official reshape path in both examples below.

For this article, we select \gamma on a small candidate grid by minimizing the fitted tree’s weighted total leaf impurity on the training split. This is a pragmatic paper-specific heuristic whose only goal is to keep the examples deterministic and easy to rerun; it should not yet be interpreted as a recommended general tuning rule for applied work.

2.1 A compact theoretical guarantee

TpT is not only a practical heuristic. In Valla and Milhaud (2026), the analysis focuses on a subsequence of record-high times: time indices whose best penalized population split score is not beaten by any later candidate time. Assumption A1 imposes separated gaps between these record-high penalized envelopes and their competitors, while Assumption A2 ensures that the relevant population-envelope peaks remain attainable by finite-depth trees. The TpT-\alpha growing rule then follows these record-high times when expanding the tree. Under these structural assumptions, and the regularity and noise conditions needed to apply the Klusowski-Tian oracle inequality for CART estimators (Klusowski and Tian 2024), the following consistency statement holds.

Theorem 1 Valla and Milhaud (2026). Assume (A1)–(A2), the TpT-\alpha growing rule, and the regularity and noise conditions required to apply the Klusowski-Tian oracle inequality for CART estimators. For every fixed record-high time t_k, consider a sequence of depth budgets K_n(t_k) increasing with the sample size at an admissible CART rate. If the approximation bias at t_k vanishes along this sequence, the estimator fitted on the realized t_k-subtree satisfies

\mathbb{E}\!\left[\left\lVert \hat f_{t_k, K_n(t_k)} - f_{t_k}^{\star} \right\rVert^2_{L^2(P_{X(t_k)})}\right] \longrightarrow 0 \qquad \text{as } n \to \infty.

This is intentionally narrower than a blanket consistency claim over all time indices. The result identifies a non-empty sequence of times at which the penalized TpT rule recovers a consistent subtree estimator. We include this result only to summarize the current theoretical status of TpT; the paper itself remains focused on software usage. For an implementation-focused article, the practical takeaway is that the TpT framework underlying the splitter now has a precise asymptotic analysis, even though the present package implementation is discussed here from an operational rather than theorem-verification standpoint.

NoteCurrent scope

The present implementation is suitable for compact reproducible examples and software-oriented demonstrations. Although the underlying estimator exposes some missing-value support, this article does not rely on arbitrary missingness patterns; systematic validation and user-facing guidance for such settings are left as future work. Monotonic constraints are explicitly disabled for TpT at the wrapper level.

4 Install, quick start, and main parameters

The official scikit-longitudinal getting-started guide is intentionally lightweight, and the same philosophy fits this article well. For a standard Python environment, the minimal installation is:

pip install scikit-longitudinal

For long-format data, the recommended TpT workflow is to first reshape the data into wide format with LongitudinalDataset.to_wide, then fit TpTDecisionTreeClassifier (or TpTDecisionTreeRegressor) on the resulting wide matrix together with its features_group metadata:

Hide/Show the code 
from scikit_longitudinal.data_preparation import LongitudinalDataset
from scikit_longitudinal.estimators.trees import TpTDecisionTreeClassifier

train_dataset = LongitudinalDataset(file_path=None, data_frame=train_long_df)
X_train = train_dataset.to_wide(
    id_col="subject_id",
    time_col="wave",
    longitudinal_columns=["marker_a", "marker_b"],
    wave_format="{feature}_t{wave}",
)
y_train = train_long_df.groupby("subject_id")["target"].first().loc[X_train.index]

test_dataset = LongitudinalDataset(file_path=None, data_frame=test_long_df)
X_test = test_dataset.to_wide(
    id_col="subject_id",
    time_col="wave",
    longitudinal_columns=["marker_a", "marker_b"],
    wave_format="{feature}_t{wave}",
)

tpt = TpTDecisionTreeClassifier(
    gamma=0.01,
    criterion="entropy",
    max_depth=2,
    min_samples_leaf=10,
    features_group=train_dataset.feature_groups(),
)

tpt.fit(X_train, y_train)
pred = tpt.predict(X_test)

6 Example 1: Subject-level classification on pbcseq

Our classification example uses pbcseq, the sequential primary biliary cirrhosis follow-up data distributed with the survival package (Therneau, Terry 2025). We keep four longitudinal biomarkers (bili, albumin, protime, and ast) and define a binary target equal to one when the subject experiences either transplantation or death by the end of follow-up. To make duration leaves visible, we retain subjects with at least two recorded visits, keep up to the first four visits per subject, index them by visit order, and reshape that variable-length long table with LongitudinalDataset.to_wide. This yields 285 subjects and between 2 and 4 visit-order waves per subject (Table 2). The resulting cohort is therefore an illustrative software example, not a substantive analysis of the full pbcseq study.

The example is run on a subject-level train/test split after reshaping. The minimal fit/predict workflow is:

This is precisely the behaviour we want to expose in the article: the time penalty regularizes the use of history without erasing it when later measurements still provide a clearly better impurity reduction.

7 Example 2: State-level regression on Produc

Our regression example uses Produc, a public US state production panel available through Rdatasets (Munnell, Alicia H. 2025). The source data contain 48 states followed yearly from 1970 to 1986. We keep three longitudinal predictors available at each wave: private capital stock (pc), employment (emp), and unemployment rate (unemp). For each state, we hold out the final recorded gross state product and predict that final_gsp from the preceding 16 yearly observations. We keep Produc deliberately: although it is an economic panel rather than an individual-level biomedical cohort, its 17 annual waves and three interpretable predictors make the effect of the TpT time penalty easy to see in a small real dataset. To keep the example readable while still producing a nonzero selected gamma and non-baseline splits on the training impurity criterion, we use the predictor subset pc, emp, and unemp together with a depth-4 tree, min_samples_leaf=1, and min_samples_split=2.

In this example we explicitly reshape the state panel with LongitudinalDataset.to_wide(...), then fit the regressor on the resulting wide matrix and its features_group metadata. The minimal workflow is:

8 Discussion

These two examples are intentionally small. Their role is not to provide a full benchmarking study, but to document a reproducible and inspectable usage path for TpT within scikit-longitudinal. Together they show that public long-format data can be reshaped through the official LongitudinalDataset API, tuned with a simple deterministic gamma heuristic for demonstration purposes, and exported as readable wave-indexed trees.

Most importantly for this article, the exported trees show both what matters and when it matters. In pbcseq, the classifier can isolate clinically meaningful biomarker thresholds at specific follow-up waves rather than collapsing the history into a single summary. In Produc, the regression tree reveals whether private capital, employment, or unemployment becomes informative early or later in the state-level trajectory. This predictor-plus-wave readability is the main practical property we wanted to make visible.

The paper also has clear limits. We deliberately keep the methodological discussion short, we do not attempt a large comparative benchmark, and the gamma-selection rule used here is only a reproducible placeholder rather than a definitive model-selection recommendation; in particular, it is an in-sample training-impurity heuristic and should not be read as validated hyperparameter tuning. On the software side, systematic validation and user-facing guidance for arbitrary missingness patterns remain future work.

Natural next steps are equally clear: implement survival-specific evaluation metrics, add richer visualization utilities such as subject-level trajectory displays inside the fitted tree, build ensemble methods on top of the current splitter, and generalize the time penalty so that prior temporal structure such as lagged predictor effects can be encoded directly. Because TpT is now integrated into the tree-building backend, these extensions are largely a question of design and validation rather than reimplementing the core split rule from scratch.

Within that scope, TpT already has the ingredients of a useful scikit-longitudinal contribution: a lightweight API, interpretable exported trees, and a growing theoretical foundation.

# Introduction

Longitudinal data, characterised by repeated measurements of the same
variables over successive time points (referred to as *waves*), are common in
medicine, economics, and the social sciences. Unlike ordinary tabular data,
they carry a temporal structure across repeated measurements of the same
covariate, and that structure is easily lost under standard preprocessing.
`scikit-longitudinal` (`Sklong`) is an open-source Python library that
addresses these challenges by providing tools for machine learning on
longitudinal data while remaining close to the familiar `scikit-learn`
ecosystem [@provost2025sklong].

This article introduces the Time-penalized Trees (TpT)
[@valla2024tpt], a recent primitive of `Sklong` that adds a new
longitudinal-data-aware decision-tree splitter to the library. It extends
standard split selection to longitudinal data by penalizing candidate splits
placed at later observation waves, allowing earlier measurements to be
preferred when impurity reduction is comparable.

Instead of reproducing the full methodological development of TpT
[@valla2024tpt], we focus on the software side of the contribution, structured
as follows. We first present the TpT split criterion in `Sklong` and briefly
recap a recent theoretical analysis showing that TpT is a consistent estimator
across a non-empty set of observation times under explicit structural
assumptions [@valla2026consistency]. Second, we describe the reproducible setup
adopted throughout the paper, including the Python environment and the
data preparation pipeline. Third, we document the TpT Application Programming
Interface (API), walking through installation, reshaping, and the main
hyperparameters. We then present two computational examples on public
longitudinal datasets, one classification and one regression, to illustrate
the splitter's behaviour. We conclude with a short discussion of the splitter's
current scope and limitations, and of directions for future work.

Tree-based methods for longitudinal or clustered data already span several
families. Model-based recursive partitioning and generalized linear model trees
target subgroup structure through parameter-instability ideas
[@zeileis2008mob; @seibold2019glmtrees]. RE-EM trees and mixed-effects random
forests incorporate random effects to account for within-subject or within-cluster
dependence [@sela2012reem; @hajjem2014merf]. Survival-tree extensions such as
LTRC trees can also accommodate time-varying covariates in censored settings
[@fu2017ltrc]. Closer to TpT, lexicographic optimisation approaches to
longitudinal decision-tree classifiers keep the standard split score and break
ties in favour of more recent features, yielding models that lean on later
waves [@ribeiro2024lexico]. TpT occupies a complementary niche: it keeps the
CART impurity objective itself and modifies the split-selection criterion
through an explicit time penalty, making the fitted tree directly readable in
terms of both predictor and wave [@valla2024tpt].

The repository is structured as required by Computo [@computo]: the paper is
written in Quarto, the environment is frozen in `environment.yml`, and the data
preparation and analysis code are kept alongside the manuscript.

# The TpT splitter in `scikit-longitudinal`

Recursive partitioning grows a tree by repeatedly splitting a parent node into
child nodes that are more homogeneous with respect to the target variable. In
other words, each split is chosen to reduce within-node heterogeneity, or
equivalently to maximize the loss of impurity from the parent node to its
children [@breiman1984cart].

For a classification node $g$, let $p_k(g)$ denote the proportion of class
$k \in \{1, \ldots, K\}$ inside the node. An impurity measure should be
nonnegative, equal to $0$ when the node is pure, maximal at the uniform class
distribution, and symmetric in the class labels. Two standard choices are the
entropy

$$
I_{\text{Ent}}(g) = -\sum_{k=1}^{K} p_k(g)\log p_k(g)
$$

and the Gini impurity

$$
I_{\text{Gini}}(g) = \sum_{k=1}^{K} p_k(g)\left(1 - p_k(g)\right)
= 1 - \sum_{k=1}^{K} p_k(g)^2.
$$

For regression, CART typically uses the node mean squared error

$$
I_{\text{MSE}}(g) = \frac{1}{N(g)}
\sum_{i: x^{(i)} \in g} \left(y^{(i)} - \bar y_g\right)^2,
$$

where $\bar y_g$ is the empirical mean response in node $g$. If a parent node
$g_p$ is split into left and right child nodes $g_l$ and $g_r$, the usual CART
goodness-of-split is the impurity decrease

$$
\Delta I(g_p; g_l, g_r) =
I(g_p) -
\left[
\frac{N(g_l)}{N(g_p)} I(g_l) +
\frac{N(g_r)}{N(g_p)} I(g_r)
\right],
$$

with $I(g)$ standing for one of the classification impurities above, or for the
MSE in regression.

At a tree node associated with parent time index $t_p$, TpT modifies this
criterion and scores a candidate split at time $t_c$ by multiplying the usual
impurity improvement $\Delta I$ by an exponential time penalty:

$$
G_{\gamma} = \Delta I \exp \left[-\gamma (t_c - t_p)\right].
$$

The hyperparameter $\gamma \ge 0$ controls how strongly later measurements are
penalized. When $\gamma = 0$, TpT reduces to ordinary impurity-based split
selection. As $\gamma$ increases, the tree becomes more reluctant to use later
waves unless they bring a clearly stronger impurity reduction.

From a user perspective, the main entry points are
`TpTDecisionTreeClassifier` and `TpTDecisionTreeRegressor`. Both estimators
operate on wide-format data together with `features_group` metadata that
encodes which columns belong to the same longitudinal feature across waves.
Long-format data must therefore be converted to wide-format beforehand, which
is handled in `Sklong` by the public `LongitudinalDataset.to_wide` API
([documentation](https://scikit-longitudinal.readthedocs.io/latest/API/data_preparation/longitudinal_dataset/);
[tutorial](https://scikit-longitudinal.readthedocs.io/latest/tutorials/long_wide_reshape/)).
We use this official reshape path in both examples below.

For this article, we select $\gamma$ on a small candidate grid
by minimizing the fitted tree's weighted total leaf impurity on the training
split. This is a pragmatic paper-specific heuristic whose only goal is to keep
the examples deterministic and easy to rerun; it should not yet be interpreted
as a recommended general tuning rule for applied work.

## A compact theoretical guarantee

TpT is not only a practical heuristic. In @valla2026consistency, the analysis
focuses on a subsequence of *record-high* times: time indices whose best
penalized population split score is not beaten by any later candidate time.
Assumption A1 imposes separated gaps between these record-high penalized
envelopes and their competitors, while Assumption A2 ensures that the relevant
population-envelope peaks remain attainable by finite-depth trees. The
TpT-$\alpha$ growing rule then follows these record-high times when expanding
the tree. Under these structural assumptions, and the regularity and noise
conditions needed to apply the Klusowski-Tian oracle inequality for CART
estimators [@klusowski2024cart], the following consistency statement holds.

::: {.theorem}
**Theorem 1 Valla and Milhaud (2026).**
Assume (A1)--(A2), the TpT-$\alpha$ growing rule, and the regularity and noise
conditions required to apply the Klusowski-Tian oracle inequality for CART
estimators. For every fixed record-high time $t_k$, consider a sequence of
depth budgets $K_n(t_k)$ increasing with the sample size at an admissible CART
rate. If the approximation bias at $t_k$ vanishes along this sequence, the
estimator fitted on the realized $t_k$-subtree satisfies

$$
\mathbb{E}\!\left[\left\lVert \hat f_{t_k, K_n(t_k)} - f_{t_k}^{\star} \right\rVert^2_{L^2(P_{X(t_k)})}\right]
\longrightarrow 0
\qquad \text{as } n \to \infty.
$$
:::

This is intentionally narrower than a blanket consistency claim over all time
indices. The result identifies a non-empty sequence of times at which the
penalized TpT rule recovers a consistent subtree estimator. We include this
result only to summarize the current theoretical status of TpT; the paper itself
remains focused on software usage. For an implementation-focused article, the practical
takeaway is that the TpT framework underlying the splitter now has a precise
asymptotic analysis, even though the present package implementation is discussed
here from an operational rather than theorem-verification standpoint.

::: {.callout-note}
## Current scope

The present implementation is suitable for compact reproducible examples and
software-oriented demonstrations. Although the underlying estimator exposes
some missing-value support, this article does not rely on arbitrary missingness
patterns; systematic validation and user-facing guidance for such settings are
left as future work. Monotonic constraints are explicitly disabled for TpT at
the wrapper level.
:::

# Example 2: State-level regression on `Produc`

Our regression example uses `Produc`, a public US state production panel
available through Rdatasets [@dataset-produc]. The source data contain
48 states followed yearly from 1970 to 1986. We keep three longitudinal
predictors available at each wave: private capital stock (`pc`), employment
(`emp`), and unemployment rate (`unemp`).
For each state, we hold out the final recorded gross state product and predict
that `final_gsp` from the preceding 16 yearly observations. We keep `Produc`
deliberately: although it is an economic panel rather than an individual-level
biomedical cohort, its 17 annual waves and three interpretable predictors make
the effect of the TpT time penalty easy to see in a small real dataset. To keep
the example readable while still producing a nonzero selected gamma and
non-baseline splits on the training impurity criterion, we use the predictor
subset `pc`, `emp`, and `unemp` together with a depth-4 tree,
`min_samples_leaf=1`, and `min_samples_split=2`.

In this example we explicitly reshape the state panel with
`LongitudinalDataset.to_wide(...)`, then fit the regressor on the resulting
wide matrix and its `features_group` metadata. The minimal workflow is:

```{python}
#| eval: false
from scikit_longitudinal.data_preparation import LongitudinalDataset
from scikit_longitudinal.estimators.trees import TpTDecisionTreeRegressor

train_dataset = LongitudinalDataset(
    file_path=None,
    data_frame=train_df[["state", "time_index", "pc", "emp", "unemp"]],
)
X_train = train_dataset.to_wide(
    id_col="state",
    time_col="time_index",
    longitudinal_columns=["pc", "emp", "unemp"],
    wave_format="{feature}_t{wave}",
)
y_train = train_df.groupby("state")["final_gsp"].first().loc[X_train.index]

test_dataset = LongitudinalDataset(
    file_path=None,
    data_frame=test_df[["state", "time_index", "pc", "emp", "unemp"]],
)
X_test = test_dataset.to_wide(
    id_col="state",
    time_col="time_index",
    longitudinal_columns=["pc", "emp", "unemp"],
    wave_format="{feature}_t{wave}",
)

reg = TpTDecisionTreeRegressor(
    gamma=selected_gamma,
    criterion="squared_error",
    max_depth=4,
    min_samples_leaf=1,
    min_samples_split=2,
    random_state=42,
    features_group=train_dataset.feature_groups(),
)

reg.fit(X_train, y_train)
pred = reg.predict(X_test)
```

# Discussion

These two examples are intentionally small. Their role is not to provide a full
benchmarking study, but to document a reproducible and inspectable usage path
for TpT within `scikit-longitudinal`. Together they show that public long-format
data can be reshaped through the official `LongitudinalDataset` API, tuned with
a simple deterministic gamma heuristic for demonstration purposes, and exported
as readable wave-indexed trees.

Most importantly for this article, the exported trees show both what matters and
when it matters. In `pbcseq`, the classifier can isolate clinically meaningful
biomarker thresholds at specific follow-up waves rather than collapsing the
history into a single summary. In `Produc`, the regression tree reveals whether
private capital, employment, or unemployment becomes informative early or later
in the state-level trajectory. This predictor-plus-wave readability is the main
practical property we wanted to make visible.

The paper also has clear limits. We deliberately keep the methodological
discussion short, we do not attempt a large comparative benchmark, and the
gamma-selection rule used here is only a reproducible placeholder rather than a
definitive model-selection recommendation; in particular, it is an in-sample
training-impurity heuristic and should not be read as validated hyperparameter
tuning. On the software side, systematic validation and user-facing guidance for
arbitrary missingness patterns remain future work.

Natural next steps are equally clear: implement survival-specific evaluation
metrics, add richer visualization utilities such as subject-level trajectory
displays inside the fitted tree, build ensemble methods on top of the current
splitter, and generalize the time penalty so that prior temporal structure such
as lagged predictor effects can be encoded directly. Because TpT is now
integrated into the tree-building backend, these extensions are largely a
question of design and validation rather than reimplementing the core split rule
from scratch.

Within that scope, TpT already has the ingredients of a useful
`scikit-longitudinal` contribution: a lightweight API, interpretable exported
trees, and a growing theoretical foundation.
